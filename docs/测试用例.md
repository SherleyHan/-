## 五、Selenium UI 自动化 (25 个，需 `-Pselenium`)

采用标准 **Page Object Model** 分层，元素定位与断言全部封装在页面对象中：

```
src/test/java/jp/go/mext/selenium/
├── base/
│   ├── BaseUITest.java      # SpringBootTest(RANDOM_PORT) + WebDriver 生命周期 + 失败自动截图
│   └── BasePage.java        # 显式等待、点击、输入、上传、JS 校验等公共动作
├── data/
│   └── UITestData.java      # 测试账号、路由、提示文案常量
├── pages/
│   ├── LoginPage.java       # loginZ000.jsp
│   ├── MenuPage.java        # menu.jsp
│   ├── Directions2030Page.java  # directions2030.jsp
│   └── ConfirmPage.java     # commonConfirm.jsp
├── LoginUITest.java         # 7 用例
├── MenuUITest.java          # 4 用例
├── Directions2030UITest.java# 10 用例
└── ConfirmUITest.java       # 4 用例
```

关键实现要点：

- 以 `RANDOM_PORT` 启动真实内嵌 Tomcat + Jasper，驱动**真实渲染的 JSP**（非 MockMvc）
- WebDriverManager 自动匹配 ChromeDriver；默认无头，`-Dselenium.headless=false` 可观察
- 用例使用独立 H2 库 `mextuitest`，避免与其它 `@SpringBootTest` 上下文重复执行 `data-test.sql`
- 每个用例前执行 `db/reset-ui-test.sql`，重置失败计数与邮件数据，保证可重复执行
- 失败自动截图到 `target/ui-screenshots/`；下载类用例统一落到 `target/ui-downloads/`
- 通过 JUnit 5 `@Tag("ui")` 与 Surefire `excludedGroups` 隔离，默认不拖慢日常构建

运行方式：

| 命令 | 效果 |
|------|------|
| `mvn test` | 排除 UI 用例，73 个用例，约 3 秒 |
| `mvn test -Pselenium` | 全量 98 个用例（含 UI），约 40 秒 |
| `mvn test -Pselenium -Dtest=LoginUITest` | 只跑指定 UI 类 |
| `mvn test -Pselenium -Dselenium.headless=false` | 打开浏览器观察执行过程 |

## 六、Postman 接口测试集合

参见 `postman/MextSurvey.postman_collection.json`，包含 9 个请求：

| 模块 | 用例 |
|------|------|
| 01 登录 | 正常登录、用户名为空、密码错误、loginConfirm |
| 02 通知邮件管理 | 打开编辑画面、执行成功、执行失败、未登录访问、压缩下载 |
| 03 数据库校验 | H2 Console 中执行的 SQL 提示 |

每个请求都附带 `pm.test` 断言，例如：
```javascript
pm.test('statusCode=0', () => pm.expect(pm.response.json().statusCode).to.eql('0'));
pm.test('has executionId', () => pm.expect(pm.response.json().message).to.include('指示ID'));
```
